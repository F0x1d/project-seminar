# ЛР 2 — обоснование актуальности ВКР

**Тема ВКР:** Разработка системы автоматического построения контуров деталей по чертежам

**Автор или участники команды:** Зотеев Максим Евгеньевич, Иванов Виктор Сергеевич

**Вклад каждого участника при командной работе:** отчёт подготовлен совместно.

**Кратко о проекте.** Система получает на вход чертёж детали в виде PDF, JPG или PNG (скан, фотография или экспорт из CAD) и строит векторный контур детали в формате DXF. Контур отделён от размерных линий, штриховки, рамки и основной надписи и приведён к масштабу. На первом этапе распознавание выполняют мультимодальные модели через API (одна модель или небольшой конвейер моделей). Конечная цель — перейти на локальные модели, которые работают без облака.

### Выводы по обзору

1. **Сложились три группы подходов.**
   - *Классическая векторизация* [6, 13]: бинаризация, утончение или разреженная выборка пикселей, аппроксимация отрезками и дугами.
   - *Нейросетевая векторизация* [1, 17]: очистка изображения, предсказание примитивов, оптимизация.
   - *Семантический разбор чертежа* [3, 4, 10, 11, 14, 15]: детекция и сегментация рамки, основной надписи, видов и размеров, затем OCR.
2. **Появилась новая группа: мультимодальные модели (VLM).** Их используют для чтения чертежей и генерации CAD-описаний [4, 7, 8, 9]. Небольшие дообученные модели по точности и частоте галлюцинаций превосходят универсальные модели, вызываемые через API [8]. Значит, переход на локальные модели реалистичен.
3. **Задача «скан или фотография → чистый контур детали» не решена.** Векторизаторы переводят в вектор всё изображение подряд, а системы семантического разбора извлекают размеры и текст, но не строят геометрию [3, 12, 16]. Универсальные VLM, по оценкам [9], неточны в координатах.
4. **Русскоязычных чертежей ЕСКД в открытых работах и датасетах почти нет.** Зарубежные системы обучены на чертежах ISO/ASME и на латинице [3, 8].
5. **Отсюда гибридная схема для проекта.** VLM или сегментационная модель определяет, где контур детали, а где размеры, штриховка и рамка; классическое компьютерное зрение строит точную геометрию; размеры, прочитанные OCR или VLM, задают масштаб.

## 3. Обзор и сравнение аналогов

Данные о продуктах проверены по сайтам и документации разработчиков на 29.10.2026.

### Прямые аналоги

- **[Scan2CAD](https://www.scan2cad.com)** (Avia Systems, Великобритания). Настольная программа для Windows и macOS: изображения и PDF → DXF, DWG, G-code. Распознаёт текст (OCR).
  - Ограничения: не отделяет контур детали от размеров и штриховки; Python API и пакетная обработка есть только в тарифе Business ($1 599 в год); Pro стоит $89 в месяц.
- **[CSoft Spotlight Pro / RasterDesk Pro](https://csdev.ru/soft/spotlight-pro/spotlight-pro-22.html)** (CSoft Development, Россия). Гибридные растрово-векторные редакторы: Spotlight — самостоятельная программа, RasterDesk — модуль для AutoCAD. Автоматически векторизуют сканы; распознают отрезки, дуги, штриховки, текст, типы линий и стрелки; раскладывают объекты по слоям по толщине линии. OCR работает на ABBYY FineReader.
  - Ограничения: только Windows; выход в DWG; размер не распознаётся как связанная сущность (число плюс размерная линия), основная надпись не распознаётся; ИИ не заявлен; публичного API нет.
- **[Autodesk AutoCAD Raster Design](https://help.autodesk.com/cloudhelp/2026/ENU/AutoCAD-RasterDesign/files/GUID-C324644D-CB2B-4F31-8817-A3EFE8763FEC.htm)** (Autodesk, США). Набор инструментов AutoCAD для векторизации отрезков, дуг и окружностей и распознавания текста.
  - Ограничения: векторизация полуавтоматическая (пользователь указывает объекты щелчками); работает только с чёрно-белым растром; требует AutoCAD.
- **[ZWVectorization Tool](https://www.zwsoft.com/news/products/zwvectorization-tool-2024)** (ZWSOFT, Китай). Плагин для ZWCAD: JPG, PNG, TIF → DWG «в один клик», объекты раскладываются по слоям по типу.
  - Ограничения: привязан к ZWCAD; PDF на входе не заявлен; размеры не распознаются.
- **[Able2Extract Professional](https://www.investintech.com/prod_a2e.htm)** (Investintech, Канада). Конвертер PDF → DWG и DXF, для сканов есть OCR.
  - Ограничения: работает с PDF, а не с JPG и PNG; сканы только трассирует, смысла чертежа не понимает.
- **[Vectorizer.AI](https://vectorizer.ai/image-to-dxf-converter)** (Cedar Lake Ventures). Облачный векторизатор на нейросетях: PNG, JPG и другие растровые форматы → SVG, EPS, DXF; есть REST API.
  - Ограничения: рассчитан на логотипы и иллюстрации; не знает масштаба и размеров; PDF на входе нет; изображение до 3 Мп.
- **[Raster2CAD](https://www.raster2cad.com)** (BeesAI). Облачный ИИ-сервис: PDF и растровые форматы → DXF и DWG, объекты разносятся по слоям.
  - Ограничения: ориентирован на архитектурные планы, а не на машиностроительные детали; работает только в облаке.

### Косвенные аналоги

- **[Potrace](https://potrace.sourceforge.net/) и [Inkscape Trace Bitmap](https://inkscape-manuals.readthedocs.io/en/latest/tracing-an-image.html).** Бесплатная локальная трассировка растра в кривые с экспортом в DXF.
  - Ограничения: никакой семантики, трассируется всё подряд; результат не точная векторная копия.
- **[OpenCV](https://github.com/opencv/opencv) (`findContours`, аппроксимация контуров).** Классические алгоритмы выделения и аппроксимации контуров.
  - Ограничения: DXF нужно формировать отдельно (например, библиотекой ezdxf); семантики нет. Это базовый инструмент геометрической части нашей системы.
- **[Werk24](https://werk24.io/).** Облачный API: принимает PDF или TIFF чертежа и возвращает размеры, допуски, GD&T и данные основной надписи в JSON.
  - Ограничения: геометрию и DXF не выдаёт; работает только в облаке; стоимость €1,25 за страницу; поддержка ЕСКД не заявлена.
- **[eDOCr / eDOCr2](https://github.com/javvi51/edocr2)** [3, 4]. Открытые научные системы распознавания размеров и основной надписи, в eDOCr2 используется VLM.
  - Ограничения: DXF не строят; ориентированы на латиницу и чертежи ISO.
- **Универсальные VLM через API (Claude, GPT, Gemini).** Распознают изображение чертежа и отвечают на вопросы о нём.
  - Ограничения по документации разработчиков: [Anthropic](https://platform.claude.com/docs/en/build-with-claude/vision) и [OpenAI](https://developers.openai.com/api/docs/guides/images-vision) прямо указывают, что координаты и локализация объектов приблизительны, а OpenAI — что модели плохо различают стили линий; [Gemini](https://ai.google.dev/gemini-api/docs/image-understanding) возвращает координаты в сетке 0–1000. Точную геометрию VLM в одиночку не дают.
- **[Deep Vectorization of Technical Drawings](https://github.com/Vahe1994/Deep-Vectorization-of-Technical-Drawings)** [1]. Открытый научный код нейросетевой векторизации.
  - Ограничения: репозиторий заархивирован; размеры и текст не отделяются; DXF не заявлен.

### Выводы по сравнению

1. **Ни одно решение не закрывает всю задачу.** Никто одновременно не отделяет контур детали от размеров, штриховки и рамки, не восстанавливает масштаб по размерам и не выдаёт DXF.
2. **Классические векторизаторы дают геометрию без смысла.** Это Scan2CAD, Spotlight, Raster Design и ZWVectorization; лучше всех типы объектов распознаёт российский CSoft Spotlight Pro. При этом результат приходится долго дочищать вручную.
3. **Сервисы «понимания» чертежей не строят контур.** Werk24 и eDOCr извлекают размеры и основную надпись, но DXF не дают; Werk24 работает только в облаке и дорог при малых объёмах.
4. **Универсальные VLM неточны в координатах.** Это подтверждают документация их разработчиков и исследования [9], поэтому одна VLM контур не построит.
5. **Что заимствуем.** Из существующих решений берём классические алгоритмы выделения контуров (OpenCV, Potrace), идею «детектор или сегментатор + OCR» для размеров [3, 14], идею проверки результатов через VLM [4] и подход к обучению на синтетических парах «растр — вектор» [1, 5].
6. **Что устраняем:**
   - отсутствие семантического разделения элементов чертежа;
   - отсутствие автоматического масштабирования;
   - зависимость от облака (за счёт перехода на локальные модели);
   - отсутствие поддержки ЕСКД.

## 4. Итоги

**Итоговая тема ВКР:** Разработка системы автоматического построения контуров деталей по чертежам

Возможное уточнение: «…по растровым чертежам с использованием мультимодальных нейросетевых моделей».

**УДК для тезиса:** 004.93:004.932

**Ключевые слова:** векторизация чертежей, распознавание конструкторской документации, контур детали, DXF, компьютерное зрение, мультимодальные модели, VLM, сегментация изображений, OCR, ЕСКД.

### Актуальность исследования

- **Массив бумажной и растровой документации большой.** На предприятиях хранятся архивы бумажных и сканированных чертежей, а по ним нужно изготавливать детали на станках с ЧПУ, лазерной и плазменной резке. Каждый такой чертёж приходится вручную перечерчивать в CAD. Этот путь — от архивного чертежа до 3D- и векторной модели — авторы [10, 11, 13] прямо называют прикладной задачей.
- **Сканы распознаются плохо.** Перевод в вектор PDF, экспортированных из CAD, в целом решён, а распознавание сканов остаётся открытой задачей [12]. Существующие векторизаторы переводят в вектор всё изображение без разбора, а сервисы распознавания размеров не строят геометрию (раздел 3).
- **Появились новые инструменты.** В 2023–2025 годах мультимодальные модели научились читать чертежи [4, 7, 9]. Небольшие дообученные модели превосходят крупные облачные [8], так что перспективна локальная работа без передачи конфиденциальной документации в облако.
- **Ниша для отечественных предприятий открыта.** Российские работы [10, 11, 14] и продукты (CSoft) показывают спрос на автоматизацию. При этом ни одно решение не поддерживает чертежи ЕСКД на основе современных моделей ИИ.

### Цель исследования

Разработать систему, которая по чертежу детали в формате PDF, JPG или PNG автоматически строит векторный контур детали в формате DXF в правильном масштабе. Работа строится в два этапа: сначала на базе облачных мультимодальных моделей, затем с переходом на локальные модели.

### Задачи исследования

1. Проанализировать методы векторизации и распознавания чертежей и существующие решения, сформулировать требования к системе.
2. Собрать тестовый набор чертежей (сканы, фотографии, PDF) с эталонными DXF-контурами; разработать генератор синтетических пар «DXF → растр с шумом».
3. Выбрать метрики качества: точность контура относительно эталона, долю правильно распознанных размеров, долю чертежей, которые не требуют ручной правки.
4. Разработать конвейер распознавания на основе API мультимодальных моделей:
   - предобработка изображения;
   - выделение видов детали и отделение контура от размеров, штриховки, рамки и основной надписи;
   - распознавание размеров.
5. Реализовать построение точной геометрии (отрезки, дуги, окружности) методами компьютерного зрения, восстановление масштаба по размерам и экспорт в DXF.
6. Перевести конвейер на локальные модели (открытые VLM и сегментационные модели, при необходимости с дообучением); сравнить качество, скорость и стоимость с облачным вариантом.
7. Провести экспериментальную оценку на тестовом наборе и сравнить с аналогами.

### Датасеты и сервисы

- **Открытые датасеты:**
  - [FloorPlanCAD](https://floorplancad.github.io/) — около 15,7 тыс. CAD-чертежей с векторной разметкой (SVG) и растровыми изображениями, лицензия CC BY-NC 4.0. Подходит для предобучения и проверки сегментации элементов чертежа.
  - [Датасеты Deep Vectorization](https://github.com/Vahe1994/Deep-Vectorization-of-Technical-Drawings) (PFP, чертежи из ABC, реальные сканы для очистки, генератор синтетики). Подходят для обучения и оценки векторизации.
  - [ABC Dataset](https://deep-geometry.github.io/abc-dataset/) — 1 млн CAD-моделей. Из него можно генерировать машиностроительные проекции и пары «растр — вектор».
  - [DeepCAD](http://www.cs.columbia.edu/cg/deepcad/) — 178 тыс. моделей с последовательностями построения (эскиз и выдавливание). Подходит как источник 2D-эскизов деталей.
- **Собственный датасет.** Открытых датасетов машиностроительных чертежей по ЕСКД с эталонными контурами нет, поэтому планируется собрать свой:
  - DXF-чертежи деталей, отрисованные в растр с имитацией сканирования (шум, поворот, размытие);
  - реальные сканы и фотографии, размеченные вручную.
- **Сервисы и библиотеки:**
  - API мультимодальных моделей (Anthropic Claude, OpenAI, Google Gemini) — этап 1;
  - открытые модели для локального запуска (например, Qwen2-VL, Florence-2 [4, 8], сегментационные модели семейства YOLO [11, 14]) — этап 2;
  - OpenCV — выделение контуров;
  - ezdxf — запись DXF;
  - eDOCr2 — базовый метод распознавания размеров.
